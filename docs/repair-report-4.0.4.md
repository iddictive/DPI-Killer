# DPI Killer 4.0.4: причины сбоев и исправления

## Почему ломалось

1. **Зависшие процессы вместо завершённой остановки.** ciadpi 17.3 оставался жив после SIGTERM. Старые экземпляры занимали порты 18082–18086, а приложение уже считало их остановленными. Теперь оно ждёт завершения своего процесса и при необходимости завершает именно его принудительно. Поздние callbacks не меняют состояние нового запуска.
2. **Watchdog принимал пропажу интернета за неисправность движка.** При недоступности и прямого соединения перезапуск прокси ничего не исправляет. Теперь исправный локальный процесс переживает сетевые перебои; восстановление требует повторных ошибок прокси при работающем прямом маршруте.
3. **Системные настройки менялись без нужной авторизации.** SCPreferences возвращал ошибку доступа. Native authorization исправлена, но macOS ограничивает срок её действия. Для постоянного доступа добавлен подписанный помощник; режим Direct оставлен для обычных подтверждений macOS.
4. **Ошибки установки самого помощника.** В новой реализации был неверный формат аргумента проверки подписи, затем неверный UserDefaults suite с собственным bundle ID, из-за которого помощник выходил сразу после запуска. Оба дефекта исправлены. Запись Background Activity теперь привязана к приложению. Повторная подпись с тем же кодом больше не вызывает переустановку.
5. **Статус отражал живой процесс, а не готовность системного прокси.** Поэтому рядом с ошибкой мог оставаться зелёный Active. У меню и Settings теперь один источник состояния; ошибка сохраняется и ведёт к нужному действию.
6. **Изменение настроек было отдельным ручным действием с небезопасным перезапуском.** Теперь изменения применяются последовательно, без Save; неверные аргументы возвращают прежнюю конфигурацию. Stop отменяет отложенный запуск.
7. **Публикация теряла подпись, обновление теряло работающий режим.** Старый CI выпускал ad-hoc приложение, несовместимое с авторизацией помощника, а установщик открывал обновлённое приложение остановленным. Подписанный выпуск отделён от CI; обновление сохраняет активный режим и проверяет подписанта.

## Что изменилось для пользователя

В меню находятся два одинаковых компактных синих переключателя: Helper / Direct и ciadpi / spoofdpi. Они отделены общей группой. Там же доступны системный прокси и оптимизация раздачи; техническое название TTL убрано из команды. Повторяющаяся строка Active/Stopped удалена, при ошибке остаётся доступное действие восстановления. Пресеты объясняют реальные параметры, а ручные изменения показываются как Custom.

Помощник не запускает движок от root и не нужен для локального прокси. Он меняет только прокси и TTL 65 через ограниченный подписанный IPC. При отключении владельца восстанавливает сохранённые значения; постороннее соединение не может снять чужой прокси. Общая политика авторизации macOS не менялась.

## Проверено

На установленном приложении: запуск/остановка, повторное использование порта, сохранение PID при изменении только прокси, переключение обоих движков, автоматическое применение, откат неверных аргументов, Stop во время изменения настроек, сохранение живого процесса при восстановлении сети. Проверки настоящих HTTP/SOCKS запросов включали серию 144 запросов на текущем Wi-Fi без ошибок и отдельную серию 48 запросов. Подписанный помощник обслуживал повторные операции спустя несколько минут после подтверждения администратора; неправильный подписанный клиент и попытка снять чужую аренду отклонены.

Принудительное завершение приложения проверило аварийное восстановление помощником: HTTP, HTTPS и SOCKS вернулись в отключённое исходное состояние, сохранённая аренда снялась. Оставшийся дочерний движок был отдельно завершён проверкой; это не доказательство его автоматической уборки после SIGKILL приложения. Установщик отклонил пакет с неправильной версией и неправильным подписантом до остановки вызывающего процесса и замены приложения.

Пользователь подтвердил работу обоих движков и улучшенные пропорции меню. Раздача телефона и влияние TTL на ограничение скорости оператора требуют проверки именно на этой сети: проверки текущего Wi-Fi не доказывают снятие ограничений раздачи. Движок не переписывался, поскольку подтверждённые причины лежали в управлении процессами, авторизации и интерфейсе приложения.

Сборка подписана Apple Development, без нотариализации. Детальные промежуточные наблюдения сохранены в [runtime-reliability.md](runtime-reliability.md); ранние checkpoints там относятся к состояниям до завершения настройки помощника.

## Выпуск и установленная версия

[Релиз v4.0.4](https://github.com/iddictive/DPI-Killer/releases/tag/v4.0.4) опубликован из коммита `ae51625`. [CI-сборка](https://github.com/iddictive/DPI-Killer/actions/runs/38611314337) прошла. Скачанный с GitHub DMG совпал с загруженным побайтно по SHA-256:

`0cb7e6b6c4921f5410ee8d31d9b224c669f90ac161354bf0a459be28323c6fe1`

Пакет содержит обе архитектуры arm64/x86_64; строгая проверка подписи проходит. Приложение установлено из скачанного DMG настоящим shell-установщиком GitHubUpdater: staging, проверка подписи и версии, остановка старого приложения, замена, запуск и smoke check завершились успешно. Установленная версия — 4.0.4; её исполняемый файл совпадает с приложением внутри DMG. Работающий SpoofDPI и системный HTTP/HTTPS-прокси автоматически вернулись на порт 18082, TTL остался 65. После обновления повторное подтверждение помощника не понадобилось.

Проверка обновлений в установленном кандидате увидела опубликованную 4.0.4. Одна загрузка через URLSession завершилась TLS-ошибкой; повторные загрузки того же пакета напрямую и через текущий SpoofDPI прошли. Причина единичной ошибки не установлена. Финальная установка проверена через исполняемый установщик, а полный повтор нажатий в окнах автообновления не завершён: инструмент управления интерфейсом перестал находить окно. Отказ от неверного пакета проверен; аварийный rollback после замены и отказ NSApplication от завершения отдельно в установленном приложении не воспроизводились.
